# StarForge — последовательность для Build

Актуально 2026-10-03. Адреса только в `DEPLOYMENT.md`. Старый GDD `Somnia_StarForge_GDD_v1.6.md` по курсу устарел: mainnet и глубина боя не следующие шаги.

Build кормить **по одному файлу**. Следующий файл не давать, пока текущий не принят. GDD не скармливать как задачу.

## Очередь

1. `docs/build/01_CLIENT_V2.md` — новый клиент и бой. Контракты не трогать.
2. `docs/build/02_FORGE.md` — кузница. Только после приёмки визуала и реплея.
3. `docs/build/03_NFT.md` — оформление NFT и торгуемое Эхо. Только после кузницы на тестнете.

Не в этой очереди: пилоты, внутренняя монета, сезоны, рейды, новые боевые эффекты, передача боевого корабля, продажа пыли.

## Приёмка между шагами

- После 1: `/battle?preview=1` показывает меши, четыре оружия, crit, dodge, last stand, kill, звук. Кошелёк проходит buy, reroll, equip, `startMatch` по старым контрактам. `frontend/` не изменён.
- После 2: salvage, reforge, ascend на тестнете. `startMatch` и библиотека боя не менялись. Новые адреса вписаны в `DEPLOYMENT.md`.
- После 3: боевой токен отдаёт нормальные metadata и помечен непередаваемым. Эхо передаётся и не читается боем.

## Ветка

Шаг 1 — ветка `client-v2`, код в `frontend-v2/`. Шаги 2 и 3 — отдельные ветки от принятого `client-v2`: `forge`, затем `nft-echo`. В `main` не сливать, пока шаг не принят.
