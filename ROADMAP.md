## Фаза 1. Приёмка боя

Одна сцена на живом `startMatch` и двенадцать кораблей из image-to-3D. Контракты, ABI и адреса не менять.

Корабли: файл `{faction}_{class}.glb` на каждую пару из трёх фракций и четырёх классов. Источник — image-to-3D по портретам или GLB, которые передал владелец. Если image-to-3D недоступен, остановиться. Не запускать `frontend/tools/build_ships.py` и не собирать корпус из примитивов.

Приёмка:

- Превью `?previewBattle=1` и бой из чека `startMatch` идут одной сценой.
- Видны четыре типа выстрела, crit, dodge, last stand, добивание, скорости 1x / 2x / Skip, карточка VICTORY или DEFEAT.
- `damageDealt` и `remainingHp` берутся из событий. Клиент урон не пересчитывает.
- Двенадцать GLB — результат image-to-3D или явная поставка владельца, не процедурный генератор.
- Визуал принят владельцем. `npm run build` в `frontend/` проходит.

Блокер этой фазы записан в [STATUS.md](STATUS.md): HTTP 400 `grok-imagine-3d`, тикет T-G99754.

## Фаза 3. NFT и Echo

Только после кузницы на тестнете. Библиотеку боя и `startMatch` не трогать.

Боевой корабль: ERC-5192, `locked` всегда true, `Locked` на минте. Реликвия ERC-1155, transfer ревертит. `tokenURI` — metadata JSON со статами из контракта. Картинка — рендер клиента. Если заливки нет, on-chain SVG силуэта, не старый портрет. Пустой `uri` реликвии не принимается.

Новый ERC-721 `StarForgeEcho`. Трансфер включён. ERC-2981 на treasury из [DEPLOYMENT.md](DEPLOYMENT.md). Полей атаки, защиты и скорости нет. Бой и кузница в боевых чтениях этот контракт не знают. Минт только из кузницы: первый именной Legendary (1/1), сет фракции, Зал 12 — одно на аккаунт. Повтор того же действия ревертит. Продажа Echo не двигает корпус. Свой маркет не писать.

В клиенте боевой токен и Echo показаны раздельно.

Приёмка:

- Кошелёк видит metadata боевого токена и флаг locked.
- Echo именного Legendary уходит на другой адрес. Корпус не уходит.
- `startMatch` Echo не читает.
- Адрес Echo записан в [DEPLOYMENT.md](DEPLOYMENT.md).
- `npm run build` в `frontend/` проходит.
