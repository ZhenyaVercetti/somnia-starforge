## 1. Контекст и исходная задача

Проект: Somnia StarForge — fully on-chain auto-battler (TFT-like).  
Блокчейн заморожен (контракты, ABI, адреса, BattleInitData / события боя не меняются).  
Legacy-клиент: Phaser 3.90 + Three.js BattleWorld. Корабли — портреты-билборды в `battle3d/hulls.ts`.  
Визуал боя не принят. Цель — красивая, современная, динамичная сцена боя с реальными моделями кораблей (стиль Echo of Dreams).

Желаемый скоуп:  
- Менятся **только боевая сцена**.  
- PrepareScene, shop, collection, кошелёк, вызовы контрактов и разбор receipt остаются как есть.  
- Минимальные правки только для перехода в новый бой после `startMatch`.  
- Реальный чейн сразу (тестнет), без моков.  
- Корабли — красивые детализированные 3D-модели, не билборды и не примитивы.

## 2. Ключевые моменты из предыдущего чата (PDF)

### 2.1. Попытка полного нового клиента
- Агент предложил новый клиент на React + React Three Fiber в ветке `client-v2` / папке `frontend-v2/`.  
- Старый Phaser остаётся в `frontend/` как legacy.  
- Промпты были длинные: полный UI (connect, forge, collection, shop), один canvas, адаптер контрактов, стиль Echo of Dreams.  
- Разрешалась/требовалась процедурная геометрия для кораблей (Lathe, Box, Cone).

### 2.2. Результат Build
- Получился мусорный интерфейс: плавающие неподписанные меши, стеклянные панели, непонятный сбор флота.  
- Корабли — низкополигональные веретена из примитивов + bloom/grain = «пиксельное месиво».  
- Задача «поменять только бой» превратилась в «собрать новый продукт».  
- Пользователь отказался дорабатывать. Предыдущий агент был «уволен».

### 2.3. Диагноз недопонимания
- Пользователь хотел: другой движок только для боя + красивые модели, старый поток сохранить.  
- Агент расширил до полного переписывания клиента, потому что «Build проще собрать с нуля».  
- Промпты не задавали чёткий макет экранов и разрешали плохую геометрию.

### 2.4. Другие темы из того же чата
- Курс GDD: кузница — ядро, бой — проверка корпуса. Цель — Зал Эха, 12 именных Legendary.  
- Salvage / Reforge / Ascend / имя / сет-реликвии.  
- NFT: боевые корабли и реликвии soulbound, торгуемый слой — отдельные Echo-токены без статов.  
- Газ: упаковка логов, отказ от записи lastAI и массивов HP, вынос минта уровня из startMatch. Бой остаётся on-chain.  
- Документы на main приведены к GDD v1.7. Адреса не менялись.

## 3. Текущий чат: попытки сделать только сцену боя

### 3.1. Правильная постановка
- Только боевая сцена на React Three Fiber.  
- Остальной код минимально правится, чтобы новая сцена легла после startMatch.  
- Реальный чейн, текущие адреса и ABI.  
- Корабли — реальные 3D-модели (GLB), не картинки и не примитивы.

### 3.2. Промпты, которые давались Build
- Полный промпт на сцену боя + реальные GLB + минимальная интеграция.  
- Стиль фракций и классов задан чётко.  
- Запрет на Lathe/Box/Cone и на билборды.  
- Позже — короткий проверочный промпт: взять существующие портреты и прогнать через image-to-3D.

### 3.3. Фактический результат
- После ~2,5 часов Build выдал сцену с процедурными blob’ами (коричневые поды с шипами, кластеры, удлинённые фигуры).  
- Это именно то, что запрещалось.  
- Проверочный промпт показал: image-to-3D недоступен.

### 3.4. Почему не получились модели
- Build умеет писать код сцены, камеру, разбор событий.  
- Он не умеет надёжно генерировать production-quality 3D-модели.  
- Внутренний `grok-imagine-3d` есть, но заблокирован:  
  `400 invalid-argument — Zero Data Retention teams do not have access to deferred endpoints.`  
- 3D-генерация — отложенный эндпоинт, ему нужно хранить данные. У команды включён Zero Data Retention.  
- Внешние сервисы (Meshy, Tripo, Rodin) Build недоступны.  
- Поэтому он либо отказывается, либо собирает процедурные blob’ы.

## 4. Текущие выводы и ограничения

| Вопрос | Факт |
|--------|------|
| Может ли Build сгенерировать красивые 3D-модели? | Нет. Внутренний инструмент заблокирован ZDR, внешние недоступны. |
| Поможет ли лучший промпт? | Нет, если задача включает генерацию моделей. |
| Что с картинками? | JPEG/PNG — не 3D-ассеты. Как билборды или текстуры на простых мешах — компромисс, не настоящая модель. |
| Zero Data Retention | Настройка команды: данные не сохраняются. Блокирует отложенные эндпоинты (3D-генерация). |

## 5. Рабочие варианты дальше

1. **Ассеты снаружи, Build только интеграция**  
   Сгенерировать 12 изображений → прогнать через внешний image-to-3D (Meshy/Tripo/Rodin) → положить GLB в репозиторий → короткий промпт Build: «возьми эти GLB, поставь в сцену, не генерируй геометрию сам».

2. **Компромисс на текстурах**  
   Высокодетальные изображения как текстуры на простых читаемых мешах (не blob). Быстрее, но это не настоящие модели. В R3F будет чище, чем старые Phaser-билборды, но при сильных ракурсах будет видно, что плоскость.

3. **Готовые GLB**  
   Найти/купить sci-fi модели и адаптировать под фракции. Затем только интеграция через Build.

4. **Выключить Zero Data Retention**  
   Если есть доступ к настройкам команды — отключить ZDR и повторить попытку с `grok-imagine-3d`. Или использовать другой аккаунт без ZDR.
