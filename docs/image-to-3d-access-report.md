# Отчёт: боевая сцена и блокировка image-to-3D

Дата отчёта: 2026-10-15.  
Репозиторий: https://github.com/ZhenyaVercetti/somnia-starforge  
Ветка: `main`. Последний продуктовый коммит на момент отчёта: `0649cb7` — «Open the new 3D battle after a real startMatch.»  
Аккаунт xAI: `ohotnik.ent@gmail.com`.  
Тикет поддержки: **T-G99754**.

Этот документ описывает, что делалось в одном чате Grok Build, что уже в гите, и почему замена кораблей через image-to-3D остановилась. Секреты, OAuth-коды и токены сюда не входят.

## 1. Что просили сначала

Нужна была только новая боевая сцена внутри существующего клиента в `frontend/`. Нельзя было переписывать магазин, коллекцию, кошелёк, Prepare и остальные экраны. Phaser-сцены должны были остаться. Единственная точка перехода: после успешного `startMatch` и разбора чека открывать новую сцену вместо старой `BattleScene`.

Условия данных:

- Сеть Somnia, chain id `50312`, RPC `https://dream-rpc.somnia.network`.
- Адреса и ABI уже лежали в `frontend/src/lib/contractAddresses.ts`. Их не меняли.
- Game `0x064fE7661b1eb52b727e562E652764b94c008383`
- Unit NFT `0x9c8784d47dA7fc4772EE617dC3A49c506A6481A1`
- Relic `0x619e19df1975A8D289545834aAff3FEEf1b84909`
- Profile `0x2C8976ECc9e9bDf939745ee61b1aD858607563d9`
- Бой играется только по списку событий из чека `startMatch`. Клиент не пересчитывает урон. `damageDealt` и `remainingHp` — истина.
- Спецэффект: байт `1` CRIT, `2` DODGE, `3` Last Stand, иначе нет.
- Каталог: фракции Empire / Voidborn / Mechanoids, классы Fighter / Cruiser / Dreadnought / Drone Swarm.

Сцена: один canvas React Three Fiber, без Phaser внутри боя. Биты: телеграф, четыре типа выстрела, крит, уклонение, last stand, добивание, камера, скорости 1x / 2x / Skip. В конце VICTORY или DEFEAT. Тонкая верхняя панель. Старые экраны не перерисовывать.

Корабли: 12 настоящих GLB, по файлу `{faction}_{class}.glb`. Не картинки, не билборды, не корпуса из `LatheGeometry` / `BoxGeometry` / `ConeGeometry` / `ExtrudeGeometry`. Если модель не получилась, не подменять её примитивом.

## 2. Что в итоге закоммичено

Коммит `0649cb7` запушен в `origin/main`.

Сделано:

- `frontend/src/battle/` — сцена R3F: поле, корабли, выстрелы, камера, проигрывание событий, верхняя панель и карточка результата.
- `PrepareScene` после успешного разбора чека вызывает `openChainBattle`. Превью из `BootScene` по-прежнему открывает старую `BattleScene`.
- 12 GLB в `frontend/public/assets/ships/`: `empire_`, `voidborn_`, `mechanoids_` на `fighter`, `cruiser`, `dreadnought`, `swarm`.
- Генератор этих GLB: `frontend/tools/build_ships.py`. Он пишет индексированные треугольные меши с нормалями и PBR-материалами напрямую в glTF. Это не классы примитивов Three.js.
- Зависимости: React 19 и `@react-three/fiber` в `frontend/package.json`. В `tsconfig.json` включён `jsx`.
- `npm run build` в `frontend/` проходил.
- Локально поднимался `npm run dev` на http://localhost:5173/. Позже процесс остановили вручную. Снова его не запускали.

Перед коммитом убрано лишнее, что не входит в продукт:

- незакоммиченные дубликаты картинок `battle_sky.jpg`, `battle_void.jpg`, `planet.jpg` и `shot_*.jpg`;
- неиспользуемый `frontend/src/utils/battleFx.ts`;
- каталог сборки `frontend/dist`;
- локальная ветка `return-to-1505`, у неё не было коммитов сверх `main` и её не было на origin.

Старые Phaser-сцены, магазин, коллекция, кошелёк и выбор флота не переписывались.

Живой `startMatch` с подписью кошелька из этой среды не отправлялся. Проверка боёвки шла в headless Chrome по временному стенду. Стенд удалён до коммита, в репозитории его нет.

## 3. Почему корабли не из image-to-3D

Официальный путь — Grok Imagine 3D, скрипт `three_d.py` из навыка game-assets, модель `grok-imagine-3d`.

Авторизация этим скриптом проходит. Список моделей возвращает HTTP 200, модель есть, вход только картинка, выход 3D. Генерация — отложенный запрос: сервис должен сохранить результат, пока клиент его скачивает.

Первый же `POST` на генерацию завершился сразу, без постановки в очередь:

```text
HTTP 400
code: invalid-argument
error: Zero Data Retention teams do not have access to deferred endpoints. Indeed, those endpoints require to store data.
```

У команды сессии включён режим Zero Data Retention. В этом режиме xAI не хранит данные запроса, а отложенный 3D-эндпоинт без хранения не работает. Meshy, Tripo и Rodin из этого чата недоступны. Обход через своё S3 в документации есть для видео и для части картинок. Для `grok-imagine-3d` такого обхода нет.

Поэтому 12 GLB в коммите `0649cb7` — авторские меши из `build_ships.py`, не результат image-to-3D. Это было сделано до прямой команды «если image-to-3D нет — остановись и ничего не подставляй».

## 4. Повторная попытка заменить корабли портретами

Отдельная задача после коммита: взять готовые портреты из `frontend/public/assets/units/portraits/` и прогнать каждый через image-to-3D. Полученные GLB поставить в боевую сцену вместо текущих корпусов. Геометрию самому не строить. Если инструмента нет или он не работает — явно сказать и остановиться.

Портреты на месте, 12 файлов. Имена портретов используют `emperial_`, файлы боя — `empire_`. До замены файлов дело не дошло.

Проверка инструмента:

- `three_d.py auth` — почта `ohotnik.ent@gmail.com`, team `e6b727ae-7a90-4c3f-bf60-9ab135a157be`, team name пустой.
- `three_d.py models` — `grok-imagine-3d` доступна в списке.
- `three_d.py generate` по `emperial_fighter.png` — сразу тот же HTTP 400 про Zero Data Retention.

После этой команды процедурные меши больше не подменялись. Боевые GLB из коммита `0649cb7` не перезаписывались.

Та же ошибка повторялась на каждой следующей проверке, включая проверку сразу после ответа поддержки «мы не видим включённого ZDR». Менялись только `expires_in_s` токена. Team id сессии не менялся.

## 5. Две разные поверхности, три team id

Путаница была не в портретах. Вход Grok Build и команда в xAI Console — не одно и то же, даже на одной почте.

| Откуда | Имя | Team ID | Что видно про ZDR |
|---|---|---|---|
| Сессия `grok login` / `three_d.py auth` | в сессии имя пустое; в консоли это личная команда Vercetti Television, создана 12 августа 2026 | `e6b727ae-7a90-4c3f-bf60-9ab135a157be` | API стабильно отвечает, что это ZDR-команда. В консоли у этой же команды кнопка **Enable**, то есть в интерфейсе ZDR выключен |
| xAI Console, вторая команда, создана 10 октября 2026 | Vercetti Television's team | `2c4776e4-2187-4f64-86e8-943e438dc873` | Кнопка **Enable**. ZDR в интерфейсе выключен. Сюда `grok login` так и не сел |
| Браузерный OAuth при принудительной привязке к команде консоли | имя не получено, сессия не сохранена | `14475b49-5556-41cf-a32d-87c75a237542` | Клиент отверг токен до записи `auth.json` |

Кнопка **Enable** на экране Team включает ZDR. Она не выключает его. Её не нажимали. Выключенный ZDR в консоли выглядит как кнопка Enable без бейджа Active. Включённый — как Active и **Disable**.

`grok.com/dashboard` (Overview, API keys, Billing, Members, Usage) ZDR не настраивает. Ключ API принадлежит команде. Запрет отложенных эндпоинтов тоже на команде, не на ключе. Смена подписки и слияние аккаунтов team id сессии не сменили: после этого `auth` снова показал `e6b727ae-…`.

## 6. Что пробовали, чтобы сесть на одну команду

### 6.1. Обычный `grok login`

Первый device-login подтвердил только почту. Выбор команды не показывался. В `config.toml` нет поля team. После входа `three_d.py auth` снова был на `e6b727ae-…`, генерация снова 400.

В выпадающем списке консоли сначала была только Vercetti Television's team (`2c4776e4-…`) и пункт Create Team. Команды сессии в списке не было. Позже, после смены подписки, в списке появились обе команды консоли. `14475b49-…` в консоли не появлялся.

### 6.2. Инструкция поддержки: прибить team в конфиге

Ответ «Sam from Cursor», AI Support Agent, тикет **T-G99754**. Суть: в `~/.grok/config.toml` добавить

```toml
[grok_com_config]
force_login_team_uuid = "2c4776e4-2187-4f64-86e8-943e438dc873"
```

затем выйти, стереть кэш `~/.grok/auth.json` и войти снова. Документация, на которую он сослался: https://docs.x.ai/build/enterprise и https://docs.x.ai/developers/faq/security.

Это было сделано. `grok logout` ответил, что кэшированной сессии нет, хотя `auth.json` ещё читался скриптом 3D. Файл `auth.json` удалили вручную и запустили `grok login`.

Браузерный OAuth открылся, страница потом показала «Connection successful». Клиент сессию не сохранил и завершился с кодом 1:

```text
Error: This deployment requires logging into team 2c4776e4-2187-4f64-86e8-943e438dc873; your login returned 14475b49-5556-41cf-a32d-87c75a237542
```

После этого `auth.json` отсутствовал. Привязку `force_login_team_uuid` убрали, чтобы вообще можно было войти. Повторный device-login прошёл как `ohotnik.ent@gmail.com` и снова записал team `e6b727ae-…`. Генерация `emperial_fighter.png` снова дала HTTP 400 про Zero Data Retention.

Итого два разных клиента входа дают два разных team id, и ни один из них не равен команде `2c4776e4-…`, которую просила привязать поддержка:

- device-login → `e6b727ae-…`;
- browser OAuth при включённом pin → `14475b49-…`, токен отброшен.

Поддержка заранее писала, что один и тот же адрес почты через пароль, Google, Apple или X может оказаться разными аккаунтами. Свести их выбором в UI не удалось: у `grok login` нет выбора команды.

## 7. Переписка с поддержкой

Адрес, указанный в документации для аккаунта и API: **support@x.ai**. `sales@x.ai` — для договоров и тарифов, не для этого сбоя.

Хронология:

1. Первое письмо ушло в поддержку. Быстрый ответ дал AI-агент, тикет **T-G99754**, инструкция с `force_login_team_uuid`. Подпись: ответы могут приходить от Cursor Support, потому что после сделки команды временно сидят в одном саппорт-инструменте.
2. Инструкцию выполнили. Результат — отказ входа и третий team id `14475b49-…`. Этот результат был сформулирован для ответа в тот же тикет.
3. После появления второй команды в консоли и смены подписки API всё ещё отвечал 400 на `e6b727ae-…`, хотя у обеих команд в UI кнопка Enable. Подготовлено новое письмо на support@x.ai. Его закрыли как дубликат и сказали ждать **T-G99754**.
4. Около четырёх дней после AI-ответа живого продолжения не было. Напоминание писали ответом в **T-G99754**, не новым тикетом.
5. Ответ человека («Z D at X») на напоминание: «We don't see any ZDR is enabled on your team.» Это совпадает с консолью и не совпадает с API.
6. Сразу после этого ответа живой вызов снова был таким: почта `ohotnik.ent@gmail.com`, team `e6b727ae-7a90-4c3f-bf60-9ab135a157be`, `POST grok-imagine-3d` → HTTP 400, `code: invalid-argument`, тот же текст про deferred endpoints. Для ответа в тикет подготовлен текст с просьбой смотреть серверный флаг команды, а не только переключатель в консоли.

## 8. На чём застряли

Застряли не на портретах, не на сцене и не на сборке.

Боевая сцена из чека `startMatch` уже в `main`, коммит `0649cb7`. Двенадцать GLB в ней — авторские меши, потому что image-to-3D на момент той работы был закрыт.

Замена этих мешей на результат image-to-3D по портретам не начата и специально не подменялась примитивами. Блок один:

- модель `grok-imagine-3d` в каталоге есть;
- сессия живая и сидит на `e6b727ae-7a90-4c3f-bf60-9ab135a157be`;
- консоль на этой команде показывает ZDR выключенным;
- API на генерации отвечает, что команда Zero Data Retention и отложенные эндпоинты ей запрещены;
- привязать логин к другой команде консоли нельзя: pin на `2c4776e4-…` отвергает токен, а без pin логин возвращается на `e6b727ae-…`;
- дашборд `grok.com/dashboard` эту метку не меняет;
- поддержка видит то же, что консоль, и пока не объяснила расхождение с телом HTTP 400.

Пока это расхождение не снимут на стороне xAI, прогон 12 портретов и подмена GLB в сцене невозможны. Делать корпуса вручную ещё раз по этой задаче нельзя: была прямая остановка.
